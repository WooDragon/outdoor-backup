## 1. 目标与不变量

用 ExifTool 决定原卡文件在日期库中的位置，用 rsync 完成备份。多天素材、伴生文件和未知日期共用一个数据流，不为每个日期启动一套备份任务。

首版应满足以下不变量：

1. 最终媒体只有一个正式目录树。临时来源视图只包含目录和受控符号链接，不保存媒体副本。
2. 一个任务只有一个 manager owner、一个实际传输 rsync 和一个状态发布者。
3. 日期规划不复制媒体、不判断已复制完成、不实现断点续传、不维护媒体内容哈希缓存。
4. 原卡保持只读。自动备份只接受 PRIMARY，拒绝 REPLICA，不修改卡的备份方向。
5. 同一来源路径的目标路由一经发布便固定。元数据补全、时区调整或规则升级不能静默复制到另一日期。
6. 元数据缺失不能造成静默漏备份。没有可靠日期的普通文件进入 `Undated`，同时报告原因。
7. 卡上删除不传播到库。未知来源身份、路径冲突、损坏状态和不可证明的工具能力应失败关闭。
8. `completed` 应表示规划、传输、同步、目标复验和状态发布均成功，不等于 rsync 单独返回 0。

本文中的“无重复空间”指不长期保存“整卡镜像 + 日期副本”两套相同媒体。这是库布局保证，不是全库内容去重保证。传输临时空间与 replaced 中安全保留旧文件的空间边界按第 9 节定义，不应为省空间删除尚未核实的旧内容。

非目标：全库内容去重、媒体转码、逐帧遥测分析、自动纠正相机时钟、自动清空卡、自动迁移旧库、历史版本浏览、PhotoPrism 自动导入或全库事务式提交。

## 2. 架构选择

### 2.1 选择：临时来源视图 + 一次 rsync

```text
只读原卡
  → 扫描普通文件 / ExifTool 提取白名单字段
  → 素材组与固定日期路由
  → 临时目录树中的受控 symlink
  → 一个 rsync 解引用传输
  → SSD 上的普通文件日期库
```

临时视图将“文件来自哪里”和“文件备份到哪里”分开。rsync 看到的相对路径就是最终相对路径；它仍从原卡读取真实文件内容。

| 候选方案 | 不采用的原因 |
|---|---|
| 整卡镜像后复制日期库 | 长期保留第二份媒体，不满足空间约束 |
| 整卡镜像加硬链接日期视图 | 虽不复制 inode，但两套可写路径相互影响；rsync 替换 inode 后还需修复链接 |
| 每天分别调用 rsync | 增加取消、计数、成功发布和 partial 生命周期，不解决来源身份问题 |
| 自写复制器、媒体 hash 数据库 | 与 rsync 重复，增加断点、校验和恢复状态 |
| 仅按 mtime 或插卡日归档 | 整理、拷贝会修改 mtime，不能代表拍摄日 |

没有历史迁移需求不是删除其他用户旧功能的理由。既有镜像模式保持默认。日期模式应显式启用，并使用新的空库根。日期库根应为已验证目标挂载点的直接子目录；这个限制不改变镜像模式的既有根选择。相等、祖先或后代关系均属于两种库根混用，不能只比较路径字符串是否不同。

### 2.2 正式目录

```text
<library>/
  .outdoor-backup/
    library.json
    routes/<SD_UUID>.json
    replaced/<job-id>/...         # rsync 更新目标时保留的旧文件
  .card-identities/<SD_UUID>.json # 复用现有来源绑定
  .logs/...
  2026/20260808/<SD_UUID>/PRIVATE/M4ROOT/CLIP/<原始文件名>
  2026/20260809/<SD_UUID>/DCIM/<原始相对路径>
  Undated/<SD_UUID>/<原始相对路径>
```

日期目录固定为 `YYYY/YYYYMMDD`。不从目录备注、文件名或任务开始时间推断日期。保留原卡相对路径和稳定来源命名空间，避免不同卡、不同相机目录内的同名文件相互覆盖。

`SD_UUID` 是既有配置中的逻辑来源身份，不是设备序列号、别名或本次插卡时间。其文件系统身份继续由 `.card-identities` 单独绑定，不在路由文件内另造一套身份规则。

日目录可供人工阅读，但它是受管路径。首版不支持在活动库中手工改名日期、来源目录或媒体文件；NAS 上已经人工整理的目录只是元数据样本，不是原卡布局证据。下游导出副本可自行整理。未来受管改名属于独立迁移功能，不能靠下一次插卡自动猜测。

### 2.3 临时视图

视图应建在 manager 私有工作目录中，根目录权限为 0700。视图内生成的父目录是实际目录，叶子全部是指向本次只读来源普通文件的链接。链接的名字和父路径来自已验证的目标路由，链接目标来自已验证的源路径。

一张卡含三天素材时，视图中同时存在三个日期目录。一次 rsync 传输整个视图。临时视图应在所有规划、校验和传输进程退出后才删除，原卡应在这些进程退出后才卸载。

| `luci-app-outdoor-backup/luasrc/model/cbi/outdoor-backup/config.lua` | 目标保存 | 显式布局选择、不同根、工具能力说明 |

根 `files/` 仍是运行时唯一来源，`outdoor-backup/files -> ../files` 应保持不变。`PRE_BACKUP_HOOK`、`POST_BACKUP_HOOK`、`RSYNC_EXTRA_OPTS` 目前没有运行时消费者，不能当作现成扩展接口。

日期模式的自动任务应只接受已配置且逻辑身份合法的来源卡。manager 应在只读挂载后、调用既有 `setup_sdcard_config` 的任何 RW 初始化分支前检查配置。配置缺席时应报告 `source_not_initialized` 并结束任务；不得重挂 RW、写卡配置或启动传输。配置非法、REPLICA 和身份不匹配仍按既有规则拒绝。

来源卡的初始化是管理员显式执行的独立操作，不属于自动日期备份。后续实现应提供独立初始化入口及手册，不以触发一次镜像备份代替初始化。镜像模式既有首次初始化行为应保持兼容。

日期规划应由一个 Perl helper 完成，使用 `Image::ExifTool` API 和标准 JSON 编解码。shell manager 负责生命周期和发布。helper 只产生私有候选路由、临时视图和结构化结果。helper 不写共享 status，不挂卸盘，不发布库状态，不调用媒体复制命令。

helper 的输入应是 manager 构造的 argv 和版本化 JSON 数据；输出应是固定 schema 的结果。不得拼接 shell 命令、eval 输出或把未验证的输出当目标路径。日期传输 profile 应保留镜像 profile 的原有公开调用兼容性，不假装现有三参数 `backup_transfer` 已支持规划接口。

## 4. 元数据证据与支持范围

本地只读调研使用了配方指定的 ExifTool 13.59。工具版本及安装模块的权威来源在 [mCPE-Release 的 ExifTool 配方](https://github.com/WooDragon/mCPE-Release/blob/main/package/exiftool/Makefile)；这里的版本是实验记录，不是新的包版本配置。

| 材料 | 已证实 | 未证实 / 不可外推 |
|---|---|---|
| Sony ZV-E1、ILCE-7CR MP4 | 视频内含 XML 拍摄时间及 offset、model、UMID 引用；有 nrtm/rtmd 轨道 | 逐帧曝光、gyro 数值；所有固件/型号的字段一致性 |
| 两款 Sony 外部 XML | NonRealTimeMeta、CreationDate、Device、UMID 引用、视频格式、色彩描述可提取 | 内外 UMID 逐值一致性；原卡命名及配对规则 |
| DJI OsmoAction5 Pro MP4 | Encoder、QuickTime 日期、内嵌原始路径；样本支持 UTC 解释 | 所有运动相机时区语义；原卡 SRT/LRF 命名 |
| DJI Mavic3 MP4 | Encoder、QuickTime 日期、djmd/dbgi 轨道 | 缺独立时区证据；用户当前无人机的型号和素材 |
| Sony ARW/JPEG 照片 | 通用 EXIF 字段可作为设计接口 | 本轮没有真实照片样本；不能标记真机验收通过 |

样本路径和文件名由用户人工整理过。人工名字不能作为设备、色彩模式、拍摄时间或伴生配对的权威证据。文档及测试仓库不应纳入原始 NAS 地址、私人目录名、GPS、设备序列号或原始 UMID 值。

本轮视频提取采用 `-fast`，未使用 `-ee` 或二进制提取。`-fast2` 在样本中遗漏了所需内部日期，因此不属于首版日期读取 profile。QuickTime 样本描述中的 `BitDepth=24` 不能作为视频 8/10 bit 的判据；位深与逐帧参数不参与日期路由。

## 5. 日期策略

### 5.1 日期表示和固定策略

日期库初始化时应固定：路由 schema、解析 profile、无 offset 时间的解释规则，以及 UTC 时间的归档时区。首版采用管理员显式给定的固定分钟偏移量；例如 +08:00，不依赖设备启动时的 TZ。首版不提供自动旅行时区或 DST 猜测。

含显式 offset 的拍摄字段按它记录的当地日期归档。已确认 UTC 语义、但不含拍摄地点 offset 的时间，转换到库的固定归档偏移量后取日期。没有 offset 的 EXIF 拍摄日期保留相机记录的当地日，不先伪装成 UTC 再转换。

库初始化后不应在线修改这些策略。升级应能继续读取既有 profile；不能读取的版本应拒绝写库，不自动重算所有路由。

### 5.2 字段来源

| 素材 | 选择规则 | 无可靠值时 |
|---|---|---|
| ARW/JPEG 等照片 | EXIF DateTimeOriginal；合并合法的 SubSecTimeOriginal、OffsetTimeOriginal | Undated；不能用 ModifyDate/文件 mtime 冒充 |
| Sony 视频 | 内嵌 Sony XML CreationDate；缺席时用已可靠关联的外 XML；再缺席时才用受测 UTC profile 的 QuickTime CreateDate | Undated |
| Sony 外 XML | 已关联则采用主视频路由；独立 XML 可用它自己的合法 CreationDate | 无日期或关联矛盾则 Undated |
| DJI 视频 | 受测设备 profile 的 QuickTime CreateDate，按该 profile 的 UTC/当地语义解释 | 不确定时区语义的型号进入 Undated |
| 其他普通文件 | 已可靠关联则采用主素材路由；否则只有经过适配的拍摄字段可决定日期 | Undated |

日期解析应验证字段格式、日期有效性、offset 范围、零日期和格式定义的未知占位值。不得按“当前年份附近”删除合法历史日期。`CreationDate` 与 `lastUpdate` 不同，Sony lastUpdate 不参与拍摄日选择。

最高优先级的合法拍摄字段决定路由。低优先级字段只在它缺席或非法时回退；已经选中高优先级字段后，fallback 字段不参与日期冲突判定。例如 Sony 内 XML 有显式 offset 时，QuickTime UTC fallback 不应按库偏移另算一天后否定内 XML。

冲突比较只覆盖同优先级的可信字段，或素材组中多个主素材的可信拍摄字段。双方均有明确 offset/UTC 语义时，规划器应先转为绝对时间，再统一到选定主字段的日期坐标。表示同一瞬间、或按字段精度得到的时间区间相互重叠时，不构成冲突。双方均为同一受测 profile 的无 offset 相机当地时间时，规划器可直接比较当地拍摄日。其他不可比较的语义应报告 `ambiguous_date_semantics`；只有这类歧义妨碍素材组确定日期时才进入 Undated，不按各自日期坐标制造假冲突。

同一日期坐标内确实给出不同拍摄日的可信 peer 字段，应使素材组进入 Undated 并报告 `conflicting_capture_date`。例如 `2026-08-09T00:30:00+09:00` 与 `2026-08-08T15:30:00Z` 表示同一瞬间；选定前者时应归入 `20260809`，即使库偏移是 +08:00 也不判冲突。修改时间和 Sony lastUpdate 不参与以上比较。

相机时钟即使错误也可能格式合法。系统不能证明其真实拍摄日，不能声称自动修正；管理员应先修正相机时钟。跨午夜视频以开始拍摄日归档，不切割内容。

## 6. 素材分组与旁车文件

分组只用于让有关联的文件采用同一路由，不用于跨卡去重，也不改变文件内容。

1. 扫描器先收集本卡所有被接受的普通文件，建立原始相对路径索引。
2. 适配器为媒体提取拍摄日期候选及可用的 recording identity。
3. Sony XML 仅在内外 UMID 引用严格相等、且唯一指向一个本卡视频时，自动加入该视频组。相同 UMID 对应多个视频时应报歧义，不猜选哪个。
4. 同目录、完全同 stem 的已声明旁车类型可配对，例如 MP4 与同 stem 的 SRT/LRF/THM。相同 stem 指向多个主素材时不配对。
5. 不把“删掉 M01 后匹配”当 Sony 通用规则。当前人工改名样本不足以授权此类规则；新增原卡命名适配器应先有真实脱敏 fixture。
6. RAW+JPEG 的同 stem 照片可作为一个组；两者可靠拍摄日不同则报告冲突并进入 Undated。
7. 无法关联的 XML/SRT/LRF/THM 仍应备份，不能因为配对失败丢弃。

主素材是新素材组的日期权威。主素材已有路由时，组应优先沿用该路由，而不是按新元数据重新计算日期。已关联旁车的文件 mtime、更新日和自身容器日期不应把它拆到另一日。非主拍摄字段只作诊断。

组内任一已有成员的固定 bucket 与主素材路由不同时，manager 应在传输前拒绝本次任务并报告 `reclassification_required`。组锚点优先沿用主素材的既有记录；没有既有主素材记录时，规划器应按固定的主素材类型优先级及原始路径字节序选择锚点，不按目录遍历顺序选择。分组变化可以补充关联记录，但不能修改已有目标位置。

每个文件只能属于一个组。重复声明、身份冲突或多个主素材竞争同一个旁车，应留下可观察的歧义原因，不能按遍历顺序决定。

旁车晚到时：若主素材已有路由，新旁车沿用它。若独立旁车已经进入 Undated，随后发现它属于已有的日期组，首版应拒绝该组的新路由变更并报告 `reclassification_required`，不偷偷搬移、留下两份或拆组假成功。管理员应在后续受管重分类功能中处理；首版不提供自动迁移。

首版只在本次卡内主素材之间建立新关联。当前卡仅剩新旁车、主素材只在历史 route 中时，规划器不进行历史猜配；旁车应按独立文件规则归档，并报告 `primary_not_present`。既有旁车路由仍保持原位置。

## 7. 来源身份、路径稳定和冲突

来源 snapshot、磁盘世代和挂载身份继续走现有守卫；磁盘世代用于检测换盘，不是持久来源 namespace。相同 SD_UUID 的文件系统 UUID 变化应拒绝绑定。格式化后的卡应通过显式初始化取得新的逻辑来源身份，不能拷回旧配置让系统默默认领旧库。

原始相对路径是同一来源中的文件槽位。路由记录应保存可用 recording identity 的摘要，例如 Sony UMID 摘要或明确语义的拍摄时间签名。该摘要只用于检测槽位重用，不是媒体内容 hash，也不是全球素材 ID。

- 已有槽位出现不同的可用 recording identity：应在实际传输前拒绝本次任务，报告 `source_slot_reused`。首版不自动加随机后缀改名。
- 身份缺席或元数据仅补全：不能证明是另一素材；保留原路由，不以新字段改变日期。
- 原路由固定且内容发生变化：应由 rsync 处理，并保留被替换的旧内容，见第 9 节。不能以路由记录证明内容相同。
- 规划器应将本次候选和该来源的全部保留路由合并检查。目标叶子重复，以及一个普通文件目标成为另一目标的目录前缀，都应在路由发布和传输前失败。目标实际存在的目录组件若是普通文件、symlink 或特殊项，也应失败，不能交给 rsync 自动类型替换。
- 卡上旧文件 `A` 已删、随后出现目录 `A/B` 时，只要新旧目标发生文件/目录前缀冲突，旧 `A` 就应留在原正式位置。反向的目录变文件冲突也应拒绝。`--backup` 和省略 `--delete` 都不能代替这一检查。
- 目标目录不能保持源文件名的大小写/Unicode 区分时，应在传输前失败，不允许 last-writer-wins。
- 没有路由记录却已有同名目标：应拒绝认领。不能以路径看起来合理为由覆盖外国文件。

物理克隆卡若同时复制了配置和文件系统 UUID，现有软件身份不能可靠区分它们；本设计不声称能识别物理卡。管理员不应让不同来源共享同一逻辑身份。

源文件名应保持原始 UTF-8 文本，不作大小写折叠或 Unicode 归一化。首版遇到不可无损表示的非 UTF-8 路径应在传输前拒绝整个任务并说明原因；不能先改名再当原名备份。

## 8. 持久路由：只管位置

### 8.1 数据边界

`library.json` 保存库 ID、布局版本、解析 profile 和固定日期策略。它不保存传输进度。`routes/<SD_UUID>.json` 是该来源唯一的路由快照，不是“已复制文件清单”。既有 `.card-identities` 继续作为来源绑定权威。

逻辑 schema：

```text
library:
  version, library_id, layout=date, parser_profile, archive_offset_minutes
routes:
  version, library_id, source_id
  entries[source_relpath]:
    group_anchor, recording_identity|null, bucket, date_reason, target_relpath
```

`bucket` 为 `YYYY/YYYYMMDD` 或 `Undated`。`target_relpath` 应严格等于 `bucket/source_id/source_relpath`，不能由元数据直接提供。所有路径应为非空相对路径，不含 `.`、`..`、空组件或绝对前缀；JSON 允许正确转义的换行和制表符。重复 JSON key、非法类型、未知版本和不同 library_id 均应拒绝。

初始默认资源上限：扫描 50,000 个接受文件，每来源路由 JSON 64 MiB，单个外 XML 8 MiB。helper 应分批提取元数据，不把全卡完整元数据加载进 RAM。超大 XML 可作为普通未知文件备份，但不解析它的元数据；扫描/路由状态超限应拒绝任务，不淘汰旧路由。这些默认值应在目标环境内存验收中验证后才能发布。

### 8.2 每来源准入与首次登记

日期模式应先以非写入方式验证来源 snapshot、卡配置、库标记和工具能力，再判定该来源的登记状态。新来源不要求整个库为空；其他来源的既有数据不阻止它登记。

| 身份绑定 | 路由快照 | 该来源的目标命名空间 | 行为 |
|---|---|---|---|
| 缺席 | 缺席 | 无目标项 | 新来源：先发布空路由，再执行既有身份 TOFU |
| 缺席 | 合法且 entries 为空 | 无目标项 | 首次登记中断：继续身份 TOFU |
| 合法且匹配 | 合法且 entries 为空 | 无目标项 | 继续首次规划，不重绑身份 |
| 合法且匹配 | 合法且 entries 非空 | 可完整、部分或尚未传输 | 已登记来源：按既有路由重跑 |
| 存在 | 缺席 | 任意 | 路由丢失，拒绝写入 |
| 缺席 | entries 非空 | 任意 | 身份状态丢失，拒绝写入 |
| 任意 | 空或缺席 | 存在目标项 | 未知/损坏状态，拒绝认领 |
| 非法、不匹配，或路由非法/版本未知 | 任意 | 任意 | 拒绝写入 |

“无目标项”应同时覆盖合法日期 bucket、Undated 和受管 replaced 树内的该 source_id 命名空间，包括普通文件、partial、目录及不支持项。首次登记检查只清点路径和类型，不读取媒体 hash，也不据此恢复路由。

空路由采用第 8.1 节的完整 schema，entries 为对象 `{}`。它是来源登记占位，不含素材映射和复制完成状态。manager 应在首次身份绑定发布之前，通过临时文件、内容校验、同步、原子 rename、再同步发布空路由。空路由发布失败时不写身份绑定；同步失败时也不进入下一阶段。之后才能调用既有身份 claim。这样身份绑定一旦存在，路由缺席就不能再解释为普通首次规划中断。

### 8.3 素材路由发布顺序

1. 获得既有 owner/lease，验证只读来源和 FD 锚定目标。
2. 按第 8.2 节准入该来源；有 cancel 或失效 lease 时不继续登记/规划。
3. 完成扫描、分组、所有冲突检查和候选视图；此时不发布任何新素材映射。
4. 在同一目标文件系统内写候选路由临时文件，校验内容并同步；原子 rename 发布，再同步。
5. 若任一步失败，不启动实际传输。临时视图和文件仅在 reader 全部退出后清理。rename 已完成而后续 sync 失败时，已发布快照可能仍可见；manager 不作无证据回滚，也不把本次当成功。
6. 发布成功后再启动 rsync。即使它只传了一部分，路由也保留，下一次重建同一路径。

“路由存在”绝不等于“目标文件存在”或“目标文件完整”。重跑应把当前全部接受文件放入视图，由 rsync 自行决定传输；不依据路由快照删掉已登记文件。

卡上已删除文件的路由应保留，库内旧文件不删除。已登记来源的路由丢失、损坏或与库标记不一致时应拒绝写库；不能扫描文件名猜回映射后继续。修复属于显式离线恢复，不是本轮默认行为。

原子 rename 是进程级发布边界。检查 sync 返回值仍不能证明 SSD 控制器在断电后一定保留数据。掉电后应验证库和路由；不一致时失败关闭。没有完整、可验证的状态备份时，不应承诺无损自动恢复路由。

## 9. rsync 合同与空间成本

本节描述日期 profile，不是目前已经存在的 argv。

日期传输应保留现有日志、进度、统计和错误分类，并采用以下语义：

| 选项 / 行为 | 作用与限制 |
|---|---|
| archive + copy-links (`-aL`) | 从受控 view 的链接目标读取，接收端写普通文件 |
| 默认 quick check（不传 `--checksum`） | rsync 比较 size + mtime；不为更新判定计算完整媒体的 checksum，可能跳过同 size/mtime 的内容变化 |
| 显式 `comparison_mode=checksum` | 管理员对本次任务选择时增加 `--checksum`；对比当前来源与对应目标，不核验历史全库 |
| `--partial-dir=.rsync-partial` | partial 与正式文件分离；本地字节级复用行为仍须真实 rsync 验收 |
| `--backup --backup-dir=<本任务受管 replaced 目录>` | rsync 更新既有目标文件时保留旧文件；这种保留不证明新旧字节不同 |
| 单次 source/view 到 library 根 | 所有日目录在同一个文件列表和进程组内 |
| 禁止 delete / ignore-existing / inplace / append | 不传播删除、不把存在当完整、不修改旧文件 inode、不赌大视频前缀不变 |

日期任务默认采用 `comparison_mode=quick`，不传 `--checksum`。自动插卡任务应始终使用这个默认值。管理员可为本次手动任务显式选择 `comparison_mode=checksum`；该选择只进入本次 manager 的不可变任务快照，不修改库策略、路由位置或下一次自动任务默认值。其他枚举值应在正式写入前拒绝，不能通过任意 rsync argv 开关该行为。

默认 quick check 适用于通常不再改写的相机原始素材。来源身份、recording identity 和路径冲突检查仍按原合同执行，但不能代替完整内容比较。同路径、同 size、同 mtime 的内容变化可能被默认模式跳过；rsync 此时既不传输新内容，也不生成 replaced。界面及摘要不应把这种检查结果称为“已逐字核验全部已有媒体”。

`--checksum` 改变的是传输前更新判断。未开启它时，rsync 仍校验实际传输文件的重建结果。显式 checksum 模式可能完整读取原卡和库中对应媒体，是深度内容对比而不是日常默认成本；它不校验卡上已不存在的历史媒体。两种模式都保持增量写入，也都不引入媒体 hash 缓存、手写内容比较器或另一套复制引擎。ExifTool 的元数据读取成本应单独记录，不与 rsync 的全文件 checksum 混为一谈。

本地 source/destination 的 rsync 默认 whole-file。首版保留该默认，不加入 `--no-whole-file`；重跑大视频可能从头传输，partial-dir 主要隔离未完成内容，不承诺字节级 delta 续传。是否切换 delta 模式属于后续独立性能取舍，不在首版暗中改变。

`.rsync-partial` 是保留组件名。源文件或目录使用这个组件时应拒绝任务，而不是被过滤后静默消失。partial 应始终位于对应受管目标目录中；不能在任意公共目录中让 rsync 信任别人创建的 partial。

`replaced/<job-id>` 由 owner 生成并保持在同一 FD 锚定库内，不接受外部路径。它保存 rsync 更新目标时保留的旧文件，不是第二套整卡镜像。size 和 mtime 均未变化的正常重跑不应产生替换副本。仅 mtime 改变且超出 rsync 比较精度时，默认 quick check 会把文件判为更新；新旧字节相同也可能重新传输并留下同内容旧文件。首版明确接受这个安全保留的空间例外，不承诺 replaced 绝无同内容副本。

显式 checksum 模式下，内容相同而仅 mtime 改变应只更新属性，不产生同内容的 replaced 文件。两种模式的区别应由实际 rsync BDD 验证。发生目标更新后，状态应报告保留旧文件的数量和位置，不把它们未经对比标成“不同内容的历史版本”。首版不自动删除 replaced，不为去掉这类偶发副本强制日常全量 checksum，也不手写去重或删除逻辑。实际 backup 行为不能满足旧文件保留合同，应阻止日期模式发布；不得省略安全网。

实际传输开始前应检查既有最低空间门槛，并估算本次新文件/变化文件、partial 和替换旧内容的空间风险。估算不是容量保证。实际 ENOSPC 应按诊断分类为失败，留下可恢复数据，不发布 completed。

不采用 `--delay-updates` 作为整批事务承诺：它仍是多个 rename，且要求额外暂存空间。一个 rsync 中的 MP4 和 XML 也不是原子素材组。

## 10. 扫描和路径安全

扫描范围是本次已验证的来源挂载。扫描器不跟随原卡 symlink，不跨子挂载；发现 symlink、FIFO、设备节点或其他不支持项应拒绝任务并列出计数，不能把它们作为可信链接透传。

应复用现有传输的配置文件、垃圾箱和系统目录排除规则，并将其作为固定扫描 profile。排除计数应单独报告。其余普通文件不应仅因扩展名未支持而被省略。

所有 view 链接在创建前应确认目标为来源内普通文件。读源、创建目录、读取路由、写目标和发布状态都应检查返回值。源拔出、读取失败、断链或目标脱离挂载应使任务失败；rsync 可先完成其他文件，这不改变非零结果。

目标文件系统应支持本设计要求的区分大小写/Unicode 文件名、普通文件与目录语义、同文件系统原子 rename。日期模式初始化应在受锁、FD 锚定的私有探测目录中验证这些能力；首批正式验收覆盖 ext4/f2fs，其他目标不能仅凭已挂载可写就宣称支持。

两种布局入口均应验证 library 标记及其祖先路径。日期初始化仅允许目标挂载点的直接空子目录；既有镜像或未知数据根不自动认领。镜像入口位于日期库内时应拒绝，不能把日期 bucket 或来源子目录当作新镜像根。标记缺席但残留路由目录也应拒绝。初始化失败产生的自有候选文件可以清理，其他既有文件不能擅删。

本设计沿用当前 shell 守卫的信任边界：管理员不能在任务进行时从外部换挂载或修改受管路径。本设计不能保证对抗并发恶意 root 的 openat 级原子路径安全。普通热拔盘、服务 stop 和磁盘身份改变仍是必须测试的故障，不属于该免责边界。

## 11. 生命周期、取消和成功发布

```text
admission + owner
  → 目标/来源/布局/工具准入
  → planning
  → 发布固定路由
  → transferring
  → drain + sync + summary + 目标最终复验
  → completed / failed / cancelled
  → 释放视图、来源挂载、锁和 lease
```

planning helper 也应由 `transfer_process_run` 管理。扫描、元数据解析和写私有视图应在该进程组内完成；manager 不能另起脱离 runner 的 exiftool reader。helper 返回后，manager 应再次检查 sticky cancel 和 lease，才允许发布路由和启动 rsync。

INT/TERM 首个取消意图保留。取消后不得开启新 reader/writer；所有进程组成员退出前不得卸卡、删除视图或释放 owner。临时规划输出不能覆盖 manager 终态。服务 stop 继续先关闭准入，再精确停止 owner，不新增 killall 或猜 PID。

planning 失败：本次不传输，旧数据和旧路由保留。路由已发布但传输失败：保留路由、已传正式文件和 partial，次次重建同一路径。rsync 非零、sync/摘要/最终目标复验/状态发布失败：不得 completed。取消优先于 completed。

进程级恢复与断电持久性不同。实际卡卸载失败和 lease 释放错误应按既有生命周期结果说明，不夸大为已经解决的故障。

## 12. 状态、UI 和下游消费者

保持既有运行状态枚举，增加 `phase=planning|transferring|finalizing`、布局信息和本次 `comparison_mode=quick|checksum`；不让旧客户端遇到无定义的新终态。metadata 子进程只产生结构化局部结果，status.sh 仍是唯一状态写入接口。

任务摘要应记录实际比较模式。`completed` 表示本轮在所选比较判据下完成了规划、传输及最终检查，不等于全库完整内容审计；默认模式尤其不能表示所有被 quick check 跳过的文件均已逐字对比。

planning 阶段显示“正在分析素材”，不发布虚构的字节完成率或 ETA。视图完成后固定 entries_total，单个 rsync 的进度不跨日期回退。状态应区分已传文件、无变化文件、排除文件、Undated、配对歧义、重分类阻断和保留旧内容。

配置页面应说明固定日期策略、原卡路径保留、默认 quick check 的检测边界，以及受管目录不能手工改名。手动任务的显式 checksum 选择应说明全量读盘成本和核验范围。布局/根/策略及本次比较模式的修改不能改变正在执行任务的快照；日期与镜像根混用应在后端拒绝，不能只做前端提示。现有 ACL 和 CSRF 应继续覆盖新增读写接口。

元数据只输出日期决策所需的白名单字段。不得把 GPS、序列号、完整 XML 或完整 ExifTool JSON 写到共享状态和公开日志。媒体路径可以出现在 owner 可读的本地任务日志；UI 应把路径和警告当文本转义，不能解释成 HTML。

消费者可能看到部分已完成文件。首版不提供全库素材组事务或外部索引器自动协调；自动消费任务应在备份 owner 释放并确认该次 completed 后运行，失败任务的组不能仅按 MP4 存在当作完整组。两者需要明确调度边界，不能假装 PhotoPrism 的独立锁就是备份锁。

上述消费者条件只是必要条件。一次 completed 只涵盖本轮接受文件，不证明历史所有预留路由或以前失败任务的素材组完整。首版不提供自动全库索引触发器；未来消费者应另行定义成功快照的范围，不能凭任意一次 completed 索引整个库。

本设计不改变 PhotoPrism 的 originals/storage 挂载，也不把日期库自动挂成可写 originals。

## 13. 清理、手工操作与恢复

旧 cleanup 把库根一级 UUID 当镜像卡目录，不能用于日期库。日期模式下，LuCI preview/确认接口和 cleanup CLI 均应返回明确“不支持此布局”，即使传入 `--force` 也不执行旧遍历。不能只隐藏按钮。

镜像清理也应先取得共享 owner/lease，并通过同一 target 守卫验证实际根。CLI 的位置参数只允许指向当前配置、已验证的镜像根，不再授权任意目录；传入挂载点本身、日期 bucket 或其他未准入根都应拒绝。这个 CLI 安全收紧应同步更新镜像操作文档和一次性测试 fixture。

清理器应在删除任何项前完成两阶段预检：核对清理根的全部祖先，再检查全部候选 UUID 子树中的日期库标记和残留路由状态。祖先或后代发现日期库/疑似损坏日期状态时，应拒绝整次清理，不先删其他 UUID。判断依据是磁盘上的标记和状态，不只是当前 UCI 模式。切回镜像模式后，此前日期库仍受保护。

首版不新增媒体删除、自动清 partial、自动清 replaced、自动删失联来源或自动重分类。后续清理应独立设计共享 owner/lease、FD 锚定、路由变更及消费者边界。

管理员应备份库元数据。缺失/损坏的路由不是“首次使用”；已有数据时应拒绝重建。只有空的新库可以初始化。恢复路由、手工改名后的修复和既有 Undated 迁移必须有显式离线操作及验收，不能藏在普通插卡中。

## 14. 依赖与交付分工

outdoor-backup 当前 canonical recipe 没有 ExifTool/Perl 依赖。mCPE 预装 CLI 只证明该固件提供能力，不证明独立安装插件也可运行日期模式。

应新增可选的日期规划子包，核心镜像模式不强拉 Perl。该子包应显式依赖核心、ExifTool provider 以及实际用到的 JSON、元数据摘要模块。打包时应核对目标 OpenWrt 的真实模块包名；不在本文凭 macOS 的 Perl 核心模块猜依赖名。

日期模式准入应检验 helper、Image::ExifTool、JSON 编解码、身份摘要，以及真实 rsync argv 所需能力。应以实际解析/小型调用检验选项，不把 `--help` 未列选项当作不支持。缺少能力应在正式路由和媒体写入前失败，不退回原卡镜像假装日期整理成功。

outdoor-backup 负责业务与 BDD。mCPE-Release 后续仅负责 provider、设备 seed/build guard 和经过审核的 feed pin；本轮不改其运行时、feed 或固件。

## 16. 已有验证与发布门槛

### 16.1 已有实验，不是目标验收

本机 `/usr/bin/rsync` 是 openrsync protocol 29、rsync 2.6.9 compatible，不是上游 rsync 3.x。仅使用 `-aL --partial --stats --itemize-changes`，在一次性目录验证了：多日普通文件、无变化零传、只传新增、删除不传播、复杂 UTF-8 路径、断链非零后重跑、默认 quick check 漏掉同 size/mtime 改变而 checksum 可检测。最终 7 个唯一场景通过；其中复杂路径 harness 初次失败，修正 bytes 捕获后定向通过，累计 8 次场景执行。

上游 rsync 源码文档证实 copy-links 会解引用、断链报错。上游源码本机编译因缺开发工具停在 configure，未执行上游二进制。上述实验没有验证本设计新增的 partial-dir、backup-dir、安全规划、路由持久化或 OpenWrt 生命周期。

### 16.2 实现和发布必须完成

- G1：取得未人工改名的 Sony 照片、视频/外 XML，以及 DJI 原卡/旁车脱敏 fixture。验证 UMID 配对与时间语义，不把当前无人机或照片标记已支持实测。
- G2：实现并执行全部 P0/P1 分支；运行现有传输、身份、目标、取消、服务、状态与 cleanup 回归。
- G3：在目标 OpenWrt/实际 rsync 和 ExifTool 包中分别验收默认 quick 与显式 checksum 的 argv、更新判据、backup-dir、partial、JSON/路径和内存上限；同 mtime 内容变化与仅 mtime 变化均应有真实测试。
- G4：在一次性测试介质上注入 ENOSPC、拔盘、中断、stop、掉电及路由状态损坏；验证非零结果与失败关闭。不能在真实备份根或 NAS 素材上测试删除。
- G5：测量大视频、重复插卡、多日、接近资源上限的 RAM、规划耗时与峰值空间；分别报告默认 quick 和显式 checksum 的读盘成本，并区分 ExifTool 与 rsync 的 I/O。没有结果不得宣称性能达标。
- G6：验收 UI 能力 gate、模式隔离、旧 cleanup 拒绝、隐私和消费者可见性；本轮不验收 PhotoPrism 自动索引。

设计评审通过只表示方案没有剩余必须修订的问题，不表示以上门槛通过，也不授权开始运行时代码、提交或部署。
